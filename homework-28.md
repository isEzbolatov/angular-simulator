# Homework 28 — Change Detection

## Задание №1. `OnPush` и изменение объекта

`ChildComponent` использует `ChangeDetectionStrategy.OnPush` и получает объект `user` через `@Input()`.

### Исходный вариант

При изменении `this.user.name = 'Eugene'` ссылка на объект не меняется. Родитель и ребёнок продолжают работать с тем же объектом, поэтому `OnPush` может не обнаружить изменение ссылки и не обновить имя в интерфейсе.

### Исправление

```ts
this.user = { ...this.user, name: 'Eugene' };
```

Оператор spread создаёт новый объект. Ссылка на `user` меняется, Angular замечает новое значение `@Input()` и обновляет `ChildComponent`.

## Задание №2. `Default` и разные триггеры

Для проверки создан `DefaultCheckComponent` со стратегией `Default`, полем `count` и `ngDoCheck()`.

| Сценарий | Интерфейс | Причина запуска проверки | `ChangeDetectorRef` |
| --- | --- | --- | --- |
| `(click)` | обновляется автоматически | событие пользователя | не нужен |
| `setTimeout()` | обновляется после таймера | завершение асинхронной задачи | не нужен |
| `Promise` | обновляется после выполнения promise | завершение microtask | не нужен |
| `HttpClient` | обновляется после ответа API | завершение HTTP-запроса | не нужен |
| `setInterval()` | обновляется на каждом тике | повторяющаяся асинхронная задача | не нужен |
| комбинированный сценарий | обновляется после каждого изменения | несколько событий и async-задач | не нужен |

`ngDoCheck()` вызывается во время проходов Change Detection. Точное количество вызовов зависит от режима приложения и других событий, поэтому его нужно наблюдать в DevTools Console для конкретного запуска.

## Задание №3. `OnPush` и `ChangeDetectorRef`

Для проверки создан `OnPushCheckComponent`.

### `markForCheck()`

Метод помечает компонент как нуждающийся в проверке. Обновление происходит во время ближайшего общего цикла Change Detection, а не обязательно мгновенно.

### `detectChanges()`

Метод запускает проверку сразу для текущего компонента и его дочерних компонентов. Поэтому изменение обычно становится видно немедленно.

### `detach()`

После `detach()` компонент исключается из автоматических проходов Change Detection. Изменение поля может произойти в коде, но интерфейс и `ngDoCheck()` автоматически не обновляются.

### `reattach()`

`reattach()` возвращает компонент в дерево Change Detection. После этого он снова участвует в следующих циклах проверки. При необходимости немедленного отображения уже изменённого значения можно дополнительно вызвать `detectChanges()`.
